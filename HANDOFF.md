## Где мы

Монолитный data-layer `lib/db.ts` разделён по доменам на `lib/db/`: категории, места, траты, аналитика и фискальные чеки, плюс типы и внутренние общие helpers. Публичный вход остаётся прежним через `lib/db/index.ts`, поэтому все существующие импорты и поведение приложения сохранены. Рефакторинг расчистил основу для следующей feature-работы — budgets/limits или другого согласованного REFACTOR-шага.

## Открытые решения и риски

- `internal.ts` сознательно не входит в barrel: его exports нужны только между доменными модулями и не расширяют публичный `lib/db` API.
- `receiptExpenseAmounts` реализован в общем внутреннем слое, потому что его используют траты и фискальные чеки, но публично реэкспортируется только через `fiscalReceipts.ts`.
- Windows Application Control по-прежнему блокирует локальный `hermesc.exe`; JS Android bundle собирается, полноценный Hermes export/EAS build нужно повторить в разрешённой среде.
- Перед общим релизом остаются ручные проверки PDF export и light/dark на авторизованном Web и физическом Android из предыдущего витка.
- История проекта: `CHANGELOG.md` append-only; `HANDOFF.md` переписывается каждый виток — оба тем же коммитом.

## Не трогать

- Публичные имена/сигнатуры `lib/db`, существующие пути импорта и dependency direction без отдельной задачи.
- Защитные `throw new Error(...)`, FX/денежную математику, компенсирующий cleanup, RLS и применённые миграции.
- Импортирующие экраны/компоненты и текущие тесты ради косметики рефакторинга — они намеренно не менялись.
- Прошлые записи `CHANGELOG.md`; релизный блок штамповать только после фактического deploy.
- Пользовательский untracked `BUGS.md`.
