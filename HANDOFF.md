## Только что сделано

- `receiptExpenseAmounts` различает legacy RSD/USD/EUR, покрытую экзотику и непокрытый произвольный код. Для покрытой валюты `amount_eur` замораживается из оригинальной суммы по её собственному EUR-base курсу, `amount_rsd`/`amount_usd` остаются `null`.
- Ручной insert/update резолвит собственный якорь покрытой валюты ровно один раз; отсутствие курса всплывает как `AnchorRateUnavailableError` до записи. Непокрытая валюта вроде THB сохраняет прежний необязательный ручной RSD-путь.
- Редактор скрывает ручной RSD для RUB/KZT/TRY/GBP/CHF, показывает debounce-превью `≈ N EUR`, а ошибку якорного курса выводит тем же тостом «не удалось получить курс». Legacy-превью RSD/EUR/USD не менялось.
- Быстрый список селектора выровнен с покрытием: RSD, USD, EUR, RUB, KZT, TRY, GBP, CHF; произвольный трёхбуквенный код остался доступен.
- Общий write-path чеков безопасно синхронизирован с новой веткой helper: покрытая валюта использует один собственный якорь, а edit без изменения даты/суммы/валюты не пересчитывает замороженные значения. Review UI не менялся.
- **Проверено:** `npm run typecheck`; 28 Jest-съютов / 279 тестов; Web export (1211 modules); Android Metro export (1642 modules). Ручной тап-тест с реальной удалённой таблицей курсов и визуальная проверка редактора на устройстве не выполнялись.

## Открытые решения и риски

- Ручной эквивалент непокрытых валют остаётся в RSD; перевод этой семантики на прямой EUR отложен отдельно, чтобы не менять уже замороженные исторические данные.
- Покрытая валюта без доступного курса не сохраняется: это намеренная гарантия против NULL-якоря, а не fallback на ручной RSD.
- Пока `ANCHOR_DISPLAY=false`, новые покрытые траты имеют `amount_rsd=null`; Home/Analytics не должны переключаться на новый display-путь частично до FX-16.
- RQ-харнесс всё ещё ждёт накопления примерно 20 пар «QR-истина + фото» перед решениями по распознаванию.

## Не трогать

- Не включать `ANCHOR_DISPLAY` и не подключать `home_currency` к Home/аналитике до FX-16.
- Для непокрытых кодов не менять ручной RSD на EUR без отдельного решения; для покрытых не писать NULL `amount_eur`.
- `DisplayCurrencyContext` пока остаётся отдельной настройкой аналитики; не смешивать его с `home_currency` неявно.
- Не повторять FX-13 SQL/backfill: Глеб уже выполнил его вручную в Supabase.
- Legacy `amount_rsd`/`amount_usd` продолжают писаться для RSD/USD/EUR до отдельно гейтируемого FX-17.
- Фото чеков, реальные данные и отчёты RQ-харнесса держать вне публичного репозитория; в git остаются только код и синтетические фикстуры.
- Итоги display-расчёта — только сумма построчно округлённых центов; итог или сумму якоря никогда не конвертировать целиком.
