## Где мы

FX-16d завершает видимую часть перехода на EUR-якорь: при просмотре Home или аналитики в валюте без сохранённых строк приложение само подтягивает недостающие исторические курсы. `ANCHOR_DISPLAY=true`; расчёты FX-16a/b и параллельная запись легаси-тройки не менялись. RQ-2 остаётся в силе: нечитаемые дата/валюта фото-чека доходят до review без тихих дефолтов.

## Только что сделано

- Добавлен quote-специфичный `ensureAnchorRatesForRange`: читает нужный диапазон, одним вызовом `sync-rates` запрашивает только непокрытые даты и перечитывает строки именно для выбранной валюты.
- Home собирает уникальные даты видимых трат, аналитика — даты трат выбранного периода; оба экрана сохраняют кэш по периоду+валюте и показывают индикатор во время ensure. Original/EUR passthrough считается сразу и не блокируется.
- После единственной попытки синка `—` остаётся только для дат, на которые источник действительно не вернул историю; ошибки синка логируются и не ломают экран.
- Тесты фиксируют ранний выход EUR/пустого списка, отсутствие лишнего sync при полном покрытии, один sync недостающих дат и quote-специфичность (`EUR→RSD` не считается покрытием для RUB).
- Проверено автоматически: `npm run typecheck`; 31 Jest-suite / 309 тестов; Web и Android production export — зелёные. Реальный вызов Edge Function и визуальный переход «лоадер → сумма» требуют ручной проверки с Supabase-сессией.

## Открытые решения и риски

- Реальный on-demand sync не проверен агентом против боевого Supabase: нужны авторизованная сессия, сеть и валютный период без заранее записанных строк.
- `—` после FX-16d означает отсутствие истории у источника после одной попытки синка; автоматических циклических ретраев намеренно нет.
- Кросс-валютные значения старых строк могут отличаться от легаси-снимков на центы — принято дизайном §5.4.
- RQ-2 и чек-лист FX-16c всё ещё требуют физической проверки на устройстве/вебе перед tester rollout.
- Ручной эквивалент непокрытых валют остаётся в RSD; перевод этой семантики на прямой EUR требует отдельного решения.

## Не трогать

- Не менять half-up и правило агрегации FX-16: итог — только сумма построчно округлённых display-центов.
- Не использовать quote-агностичные `hasAnchorRateOnOrBefore` / `ensureAnchorRatesFor` для display-autosync.
- Не прекращать запись легаси-тройки и не удалять `convertAll` до отдельного FX-17 после обкатки.
- На receipt review не подставлять дату, RSD или домашнюю валюту молча; `null` значит «спросить человека».
- Для непокрытых кодов не менять ручной RSD на EUR без отдельного решения; для покрытых не писать NULL `amount_eur`.
- Не повторять FX-13 SQL/backfill: Глеб уже выполнил его вручную в Supabase.
- Фото чеков, реальные данные и отчёты RQ-харнесса держать вне публичного репозитория.
