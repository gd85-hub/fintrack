## Открытые решения и риски

- **Расхождение с Figma:** спека объявляет глобальный `radius/md = 16`, в репозитории `scale.radius.md = 14`. Не менял: у токена есть сторонние потребители, нужна отдельная задача с проверкой каждого. Для кнопки это расхождение неважно — она читает явные `radius.buttonMedium/buttonLarge`.
- Легаси-карта `theme.sizes.buttonHeight` (48) живёт параллельно `scale.size.controlMd` и используется ~50 экранами. Это предсущий компат-слой; её миграция = широкий рефакторинг токенов, в DS-01 он вне скоупа.
- `:focus-visible` в react-native-web точного эквивалента не имеет: реализовано эвристикой «фокус после нажатия указателем рамку не поднимает». Если понадобится точное поведение — нужен настоящий CSS `:focus-visible` через web-only стиль.
- Рамка фокуса сознательно только для веба: на Android оверлей за границами скруглённого вью может обрезаться, а у тач-таргета клавиатурного фокуса нет.
- Визуальная проверка на устройстве не проводилась: Button пока не отрисован ни на одном экране. Матрица закрыта render-тестами, но не глазами.

## Не трогать

- Не менять глобальный `scale.radius.md` и легаси `theme.sizes.*` без отдельной задачи с ревизией потребителей.
- Не дублировать токены: у кнопки свои радиусы и высоты уже есть, новые варианты заводить только из опубликованной спеки Figma.
- Не делать Neutral собственные disabled/focus токены — по контракту они наследуются от Primary.
- Не возвращать `disabled` для состояния loading: кнопка обязана сохранять фокус и при этом не срабатывать повторно.
- Не включать `supabase/.temp/*`, `.env` и чужую незакоммиченную работу BE-01 в коммиты DS-01.
