## Открытые решения и риски

- Offset pagination полна для стабильного набора, но несколько HTTP-запросов не разделяют транзакционный snapshot; конкурентные insert/update/delete могут сдвинуть offsets. Snapshot consistency потребует отдельного server-side RPC/transaction дизайна.
- Полный platform boot не выполняется в BE-01, поскольку UI не менялся; typecheck и Jest обязательны.
- Export currency contract всё ещё требует отдельного продуктового решения (BUG-3), независимо от полноты выборки.

## Не трогать

- Не менять финансовые значения, FX/EUR-anchor, округление, схему, RLS или production data в рамках pagination-задач.
- Не возвращать частичный financial dataset при ошибке страницы.
- Не использовать count как условие полноты и не предполагать, что server cap равен запрошенному page size.
- Не включать `supabase/.temp/*`, `.env` или другие локальные файлы в коммит.
