## Результаты проверок

`npx tsc --noEmit` чисто; `npm test` — 35 наборов / 428 тестов (новых тестов задача не требовала: логика экрана не менялась, контракт Button уже покрыт).

Экран прогонялся в Chrome 156 на dev-сервере, `http://localhost:8081/sign-up`, окно 1024×900:

- **Геометрия и ширина.** Высота 48, ширина 640 = ширина формы (`fullWidth` действительно заполняет контейнер), скругление 14, `min-width: 88px`, подпись `Inter_500Medium` 14 px.
- **Светлая тема** — фон `#0071a6`, подпись белая. **Тёмная** — `#35a7e8` и `#001727`.
- **Hover** — `#005984` (`action/primary/hover`).
- **Keyboard focus** — Tab с поля пароля: `:focus-visible = true`, кольцо `solid` 2 px, отступ 2 px, цвет `#005984`. Shift+Tab убирает кольцо (`outline-width: 0`).
- **Loading и aria-busy** — во время запроса `aria-busy="true"`, спиннер есть, строка подписи с `opacity: 0`, ширина 640 и высота 48 не меняются, `tabindex` остаётся `0`, фокус на кнопке. После ответа `aria-busy="false"`, спиннер снят.
- **Блокировка повторной активации — измерена, а не предположена.** Во время запроса два клика подряд плюс Enter плюс пробел: счётчик перехваченных вызовов `/auth/v1/signup` остался равен **1**.
- **Ошибка** — перехваченный ответ 422 `User already registered` даёт «Пользователь с таким email уже зарегистрирован.», то есть маппинг `localizedAuthError(..., 'sign-up')` на месте.
- **Подтверждение email** — перехваченный ответ с пользователем и без сессии переводит экран на «Проверьте почту» с адресом в тексте и ссылкой «Перейти ко входу».
- Консоль чистая на всех загрузках.

**Как проверялось без создания пользователей.** В самой странице патчился `window.fetch`: любой запрос на `/auth/v1/signup` до Supabase не доходил, вместо него возвращался заранее собранный ответ (422 для ошибки, объект пользователя без `access_token` для подтверждения почты) с задержкой, чтобы снять состояние Loading. Счётчик перехватов подтверждает, что ни один запрос регистрации не ушёл наружу. Код приложения при этом не менялся; ключ `theme`, который ставился для проверки светлой темы, и эмуляция размера окна после проверки убраны.

## Чего проверить не удалось

**Pressed на этом экране не снят.** Панель браузера в сессии не рисует кадры: `requestAnimationFrame` не тикает вовсе, а `setInterval` дросселируется примерно до секунды, при этом клик инструмента — быстрые down/up, которым RNW добавляет ещё 50 мс задержки перед press-in. Нажатый фон `#004061` в выборку не попал ни разу. Состояние Pressed приходит из общего компонента, не менялось этой задачей и покрыто тестами `buttonSurface` на всех шести типах в обеих темах.

## Открытые решения и риски

- **Кнопка регистрации стала скруглённее**: было `theme.radii.button` = 10, стало `radius/button/medium` = 14, как в Figma. То же было у входа и `PeriodSelector`.
- **Поведение Disabled сменилось на Loading**: раньше кнопка на время запроса получала `disabled` и выпадала из порядка обхода, теперь она `loading` — фокус сохраняется, активация блокируется. Это контракт DS.
- **`accessibilityState` на вебе читается только для `disabled`** (его ставит сам `Pressable`); `busy` доходит благодаря добавленному в DS-01.5 `aria-busy`. Для `checked`, `selected`, `expanded` понадобятся свои `aria-*` пропы, когда появятся такие компоненты.
- **Android не проверялся на устройстве.** Все измерения — веб.
- **`fullWidth` в строке с соседями переполнит её** (`width: '100%'` + `flexShrink: 0`): распределение места — ответственность родителя.
- Толщина штриха спиннера и значков не настраивается; числовой `size` у `ActivityIndicator` игнорируется на iOS.
- Файл маршрута Playground всё равно попадает в production-бандл: Expo Router не умеет исключать маршрут из сборки.
- Расхождения прошлых витков в силе: поля ввода скруглены `radius.sm` при `radius/md` = 16 в Figma, `scale.size.fieldHeight` 40 против `size/control-lg` 56, высоты чипов 28/36 против 32/40, элементы нижнего таб-бара на legacy `theme.radii.button` = 10 против `radius/sm` = 12, `radius/xs` не сверен.

## Не трогать

- Не возвращать на экраны входа и регистрации `disabled={submitting}`: подача закрывается через `loading`, иначе кнопка теряет фокус и встроенный спиннер.
- Не убирать `accessibilityLabel` с этих кнопок: он сообщает, что именно происходит, а `aria-busy` сообщает только факт занятости.
- Не убирать `aria-busy` в пользу одного `accessibilityState`: на вебе состояние снова перестанет озвучиваться.
- Не убирать `alignSelf: 'stretch'` из `fullWidth`, оставив один `width: '100%'`, и наоборот: вместе они покрывают оба направления родителя.
- Не возвращать проп `pointerEvents` на обёртку спиннера: он устарел и шумит в консоли на каждый рендер.
- Не ослаблять гейт `isDevOnlyRouteEnabled` до проверки на истинность: только `=== true`.
- Не ставить ссылку на `/ds-playground` в интерфейс приложения и не заводить пустые секции под ещё не написанные компоненты.
- Не использовать `ThemeOverride` на обычных экранах: он намеренно игнорирует настройку пользователя и ничего не сохраняет.
- Не возвращать эмуляцию `:focus-visible` через `onPressIn`/`pointerFocus` и не менять скрытое состояние кольца на `outlineStyle: 'none'`.
- Состав Component Set в Figma проверять по родительским связям (`parent.id`), а не по префиксу node id.
- Не проверять семантические привязки токенов только на production-палитрах; для этого есть `labelledPalette()` в `lib/__fixtures__/buttonPalette.ts`.
- Не удалять `icon`/`iconPosition` без отдельной задачи: помечены `@deprecated`, но остаются публичным API.
- Не включать `dist/`, `supabase/.temp/*`, `.env` или незакоммиченную работу BE-01 в коммиты дизайн-системы.
