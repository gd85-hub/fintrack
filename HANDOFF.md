## Открытые решения и риски

- Миграция перепривязывает финансовые ссылки по паре «владелец + имя категории»; до/после применения нужно сохранить и сравнить смысловой срез сумм/количества по имени.
- До применения миграции новый клиент ожидает личные категории, поэтому миграцию и обновлённую сборку нужно выпускать согласованно.
- Реальный сценарий регистрации, полный CRUD и перенос связанных данных агентом против production Supabase не проверялись.

## Не трогать

- NULL-шаблон категорий: он нужен `seed_user_categories()` для новых аккаунтов.
- RLS категорий: чтение шаблонов и запись только своих строк остаются действующим security-контрактом.
- Личную `uncategorized` нельзя удалять или использовать источником merge; это fallback для удаления и распознавания.
