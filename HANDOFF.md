## Только что сделано

- `components/ds/SearchField.tsx` — самостоятельный компонент на настоящем controlled `TextInput`. Скруглённая строка без границы, лупа слева присутствует всегда, справа опциональный значок — декоративный или кнопка. Ни плавающего лейбла, ни подсказки, ни текста ошибки; ни hover, ни pressed, ни error, ни read-only — в контракте их нет. Общую инфраструктуру с Input Field намеренно не выносил.
- `lib/theme.ts` — один новый токен `field.searchFill`: light `#f4f6f8`, dark `#ffffff08` (авторские 0.032 в 8-битной альфе). Остальные привязки взяты из существующих токенов.
- `app/ds-playground.tsx` — три секции: состояния (пустое, заполненное, disabled, disabled заполненное), правый значок (декоративный, рабочая очистка, disabled с действием) и живой поиск с подстановкой запроса и реакцией на Enter.
- `lib/__tests__/dsSearchField.test.tsx` — 35 тестов.

### Геометрия и привязки

| Параметр | Значение | Токен |
|---|---|---|
| Высота корня | 44 | `size.touchTarget` |
| Высота строки | 40 | `size.fieldHeight` |
| Радиус | 999 | `radius.pill` |
| Горизонтальный паддинг | 16 | `space[4]` |
| Зазор | 8 | `space[2]` |

| Правый значок | 20 | `size.iconMd` |
| Кольцо фокуса | 2 px, отступ 2 | `stroke.focusRing`, цвет `field.softFocusBorder` |

Заливка `field.searchFill`, значение `text.primary`, плейсхолдер `field.softPlaceholder`, оба значка `icon.secondary`. Disabled: заливка `field.subtleDisabledFill`, текст и плейсхолдер `field.disabledContent`, оба значка `icon.disabled`.

Корень на 4 px выше строки, поэтому кольцо (2 отступ + 2 ширина) укладывается ровно в него и ничем не срезается. Фокус рисуется браузерным `outline` — он не участвует в раскладке и заменяет собственное кольцо браузера, а не добавляется к нему.

## Результаты проверок

`npx tsc --noEmit` чисто; `npm test` — 40 наборов / 563 теста (было 528), прогнал трижды. Мутации «disabled-значок на field-токен», «searchFill → softFill», «лупа 18 → 20» и «disabled берёт жест» роняют от 1 до 3 тестов каждая.

Браузер (Chrome 156, `/ds-playground`, 8 живых полей поиска, светлая и тёмная, 1024 и 375):

- **Геометрия.** Строка 40 × радиус 999 внутри корня 44, паддинг 16, текст начинается на **42 px** от края строки — ровно x=42 из варианта Figma (16 + 18 + 8). Лупа 18 × 18.
- **Светлая.** Заливка `rgb(244,246,248)`, значение `rgb(18,27,33)`, лупа `rgb(83,92,98)` = `icon.secondary`, у disabled текст `rgb(152,160,165)`.
- **Тёмная.** Заливка `rgba(255,255,255,0.03)` против disabled `rgba(255,255,255,0.02)` — в тёмной эти два токена наконец различимы, в светлой они совпадают. Лупа `rgb(168,168,168)`, у disabled `rgb(92,92,92)` = `icon.disabled`. Значение `#f2f2f2`.
- **Активация.** Нажатие по левому паддингу, по самой лупе, по правому паддингу и по верхней кромке — каждое отдаёт фокус в `TextInput`. Нажатие внутри текста попадает прямо в `INPUT`, то есть нативная установка курсора сохранена.
- **Правый значок.** Цель 20 × 40 с именем «Очистить поиск». Нажатие в 3 px от верха цели — **вне** глифа 20 × 20 — очистило запрос `кофе` → пусто и **не** увело фокус в поле.
- **Фокус.** В покое `outline: solid 0px` — собственного кольца браузера нет. В фокусе `solid 2px` с отступом 2 px цветом `#005984` (светлая) и `rgba(113,194,247,0.78)` (тёмная); высота, ширина, x и паддинг не изменились.
- **Disabled.** Настоящий атрибут `disabled` на input, `readOnly`, кольца нет никогда, жест поле не берёт. Из 8 полей 5 в порядке обхода, 3 — нет.
- **375 px.** Строки 302 × 40 в корне 44, цель значка 20 × 40. Ошибок в консоли нет.

**Оговорка по методу.** В панели браузера `document.hasFocus()` равен `false`, поэтому браузер не доставляет события фокуса: `element.focus()` меняет `activeElement`, но React-обработчик не запускает. Фокус в проверках выше доставлялся явным `focusin` — это **синтетическая** часть. Нажатия — синтетические pointer-события по реальным координатам, то есть тот же код responder'а, что и у настоящего клика. Настоящие Tab и Shift+Tab в этот виток не прогонялись; вместо них проверен состав остановок в DOM.

## Открытые решения и риски

- **Кольцо фокуса только в вебе.** Как и у Button, outline-свойства применяются при `Platform.OS === 'web'`; на нативе клавиатурного кольца у поля поиска нет. Input Field, наоборот, показывает фокус внутренней границей — три компонента, две трактовки, обе осознанные.
- **Лупа 18 px — локальная метрика:** семантического токена на 18 в шкале нет, заводить новый задача не разрешала.
- **Очистка запроса — дело вызывающего.** Компонент сам значение не трёт, только зовёт `onTrailingIconPress`.
- **Debounce, фильтрация и запросы не входят в компонент** — по условию задачи.
- **Общая инфраструктура с Input Field не вынесена** намеренно; если появится третий похожий ввод, абстракцию стоит обсуждать отдельно.
- **Android на устройстве не проверялся.**
- Экраны приложения продолжают пользоваться легаси-токенами поля и собственными `TextInput`.

## Не трогать

- Не добавлять Search Field состояния hover, pressed, error или read-only: в контракте их нет.
- Не привязывать disabled-значки к `field.disabledContent`: оба глифа намеренно сидят на `icon.disabled`, чтобы не разъезжаться между собой.
- Не оборачивать поле в `Pressable` ради активации: появится лишняя остановка в Tab и сломается установка курсора нажатием.
- Не убирать `pointerEvents: 'none'` с лупы и декоративного значка.
- Не растягивать ширину цели правого значка: она отнимет нажатия у конца строки.
- Не называть поля цветовых контрактов `value`: плагин reanimated принимает `.value` в инлайновом стиле за shared value и засоряет консоль.
- Не заменять легаси-токены `field.fill` / `field.border` / `field.borderFocus` / `field.borderError` новой семьёй: на них держатся существующие экраны.
- Не использовать `field.softPlaceholder` для значков Input Field — они намеренно остались на `field.placeholder`.
- Не убирать компенсацию паддинга у Input Field при утолщении границы.
- Не заменять `readOnly` на `editable`: `editable` устарел в react-native-web и предупреждает на каждый рендер.
- Не сводить `disabled` и `loading` в один флаг на кнопках входа, регистрации и обратной связи.
- Не убирать `aria-busy` у Button и `aria-invalid` / `aria-describedby` у InputField: `accessibilityState` на вебе до DOM не доходит.
- Не убирать строчные обёртки `centeredAction` и `doneRow`.
- Не ослаблять гейт `isDevOnlyRouteEnabled` до проверки на истинность: только `=== true`.
- Не ставить ссылку на `/ds-playground` в интерфейс приложения и не заводить пустые секции под ещё не реализованные компоненты.
- Не использовать `ThemeOverride` на обычных экранах.
- Не возвращать эмуляцию `:focus-visible` через `onPressIn`/`pointerFocus` и не менять скрытое состояние кольца Button на `outlineStyle: 'none'`.
- Состав Component Set в Figma проверять по родительским связям (`parent.id`), а не по префиксу node id.
- Не проверять семантические привязки токенов только на production-палитрах; для этого есть `labelledPalette()` в `lib/__fixtures__/buttonPalette.ts`.
- Не включать `dist/`, `supabase/.temp/*`, `.env` или незакоммиченную работу BE-01 в коммиты дизайн-системы.
