## Где мы

FX-16c включён: `ANCHOR_DISPLAY=true`. Home и аналитика теперь показывают суммы из замороженного EUR-якоря по историческому курсу в домашней/выбранной валюте. Герой Home — одна сумма в домашней валюте; аналитика получила модальный переключатель всех поддерживаемых валют. Легаси-тройка продолжает писаться параллельно, поэтому аварийный откат — вернуть флаг в `false`. RQ-2 остаётся в силе: нечитаемые дата/валюта фото-чека доходят до review без тихих дефолтов.

## Только что сделано

- Проверено предусловие включения: `.env` и единственный EAS build URL смотрят на один Supabase-проект; журнал проекта фиксирует, что FX-13 вручную выполнен на этой базе.
- `ANCHOR_DISPLAY` переведён из `false` в `true`; логика Home/аналитики не менялась.
- Home считает герой, дни, покупки и строки в домашней валюте; original/EUR passthrough не требуют курса, старая строка приблизительных EUR/USD скрыта.
- Аналитика считает итог, категории, места, fixed/variable и темп как сумму построчно округлённых display-значений; переключатель предлагает восемь валют и запоминает выбор.
- При недоступном историческом курсе агрегат показывает `—`, а drilldown-строка — оригинальную сумму; неверный ноль не подставляется.
- **Автоматика:** `npm run typecheck`; 31 Jest-suite / 304 теста; Web и Android production export с включённым флагом — зелёные.
- **Ручная проверка обязательна до tester rollout:** чек-лист A–D (Home, аналитика, FX-15, честный fallback) должен пройти Глеб; при расхождении A–C сразу вернуть флаг в `false`.

## Открытые решения и риски

- Физическая проверка A–D ещё не выполнена агентом: нужна реальная сессия и устройство Глеба. До неё новый билд не отдавать тестерам.
- Просмотр валюты без исторических EUR-base строк честно даёт `—`; автоподтягивание курса при просмотре осознанно вне FX-16c.
- Кросс-валютные значения старых строк могут отличаться от легаси-снимков на центы — принято дизайном §5.4.
- RQ-2 вручную на устройстве/вебе тоже ещё не проверен: фото без даты должно дойти до review с требованием даты; обычный чек — работать как раньше.
- Ручной эквивалент непокрытых валют остаётся в RSD; перевод этой семантики на прямой EUR требует отдельного решения.
- RQ-харнесс всё ещё ждёт примерно 20 пар «QR-истина + фото» перед решениями по распознаванию.

## Не трогать

- При любом расхождении чек-листа FX-16c не чинить данные и не удалять fallback: сначала вернуть `ANCHOR_DISPLAY=false`.
- Не прекращать запись легаси-тройки и не удалять серверные разбивки/`convertAll` до отдельного FX-17 после обкатки.
- На receipt review не подставлять дату, RSD или домашнюю валюту молча: `null` значит «спросить человека», сохранение остаётся заблокированным.
- Не возвращать выбрасывание драфта при нечитаемой дате/валюте; save-пути принимают только заполненные значения.
- Для непокрытых кодов не менять ручной RSD на EUR без отдельного решения; для покрытых не писать NULL `amount_eur`.
- Не повторять FX-13 SQL/backfill: Глеб уже выполнил его вручную в Supabase.
- Итоги display-расчёта — только сумма построчно округлённых центов; итог или сумму якоря никогда не конвертировать целиком.
- Фото чеков, реальные данные и отчёты RQ-харнесса держать вне публичного репозитория; в git остаются только код и синтетические фикстуры.
