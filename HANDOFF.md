## Где мы

FX-15 завершён и его денежные гарантии дополнительно залочены регрессионными тестами. RUB/KZT/TRY/GBP/CHF сохраняются через собственный EUR-якорь без ручного RSD; Home и аналитика пока используют прежнее отображение, `home_currency` ещё только хранится, `ANCHOR_DISPLAY=false`. По сообщению Глеба, FX-13 уже выполнен вручную в Supabase; повторно его не запускать.

## Только что сделано

- В чистом тесте `receiptExpenseAmounts` зафиксировано: покрытая валюта с отсутствующим (`null`) или неположительным (`0`) якорем бросает ошибку, а не возвращает NULL `amount_eur`.
- В существующем mock-harness `updateFiscalReceipt` добавлена регрессия заморозки: правка описания KZT-чека без смены даты/суммы/валюты не вызывает anchor resolver и не включает `amount_eur`/`amount_rsd`/`amount_usd`/`fx_rate_date`/`original_currency` в update payload.
- Отдельный тест фиксирует перезаморозку при смене суммы: ровно один resolve для `KZT`, новый `amount_eur` считается half-up из оригинальных центов и собственного курса, legacy RSD/USD и `fx_rate_date` остаются `null`.
- Кода продукта, зависимостей и схемы не меняли.
- **Проверено:** `npm run typecheck`; 28 Jest-съютов / 282 теста. Web/Android export не повторялся, поскольку bundle/source в tests-only задаче не менялись.

## Следующий шаг

**FX-16:** свитчер валюты отображения и подключение Home/аналитики к `home_currency` через якорный display-расчёт; только в этой отдельной задаче флипнуть `ANCHOR_DISPLAY` и проверить равенство итогов как суммы построчно округлённых значений.

## Открытые решения и риски

- Ручной эквивалент непокрытых валют остаётся в RSD; перевод этой семантики на прямой EUR отложен отдельно, чтобы не менять уже замороженные исторические данные.
- Покрытая валюта без доступного курса не сохраняется: тест теперь явно закрепляет гарантию против NULL-якоря.
- Пока `ANCHOR_DISPLAY=false`, новые покрытые траты имеют `amount_rsd=null`; Home/Analytics не должны переключаться на новый display-путь частично до FX-16.
- RQ-харнесс всё ещё ждёт накопления примерно 20 пар «QR-истина + фото» перед решениями по распознаванию.

## Не трогать

- Не включать `ANCHOR_DISPLAY` и не подключать `home_currency` к Home/аналитике до FX-16.
- Для непокрытых кодов не менять ручной RSD на EUR без отдельного решения; для покрытых не писать NULL `amount_eur`.
- `DisplayCurrencyContext` пока остаётся отдельной настройкой аналитики; не смешивать его с `home_currency` неявно.
- Не повторять FX-13 SQL/backfill: Глеб уже выполнил его вручную в Supabase.
- Legacy `amount_rsd`/`amount_usd` продолжают писаться для RSD/USD/EUR до отдельно гейтируемого FX-17.
- Фото чеков, реальные данные и отчёты RQ-харнесса держать вне публичного репозитория; в git остаются только код и синтетические фикстуры.
- Итоги display-расчёта — только сумма построчно округлённых центов; итог или сумму якоря никогда не конвертировать целиком.
