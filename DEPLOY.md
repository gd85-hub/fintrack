# Fintrack — деплой (универсальная инструкция)

Как в любой момент выкатить Fintrack на **web** (EAS Hosting) и **мобилу** (EAS Build, Android). Клади в корень репозитория рядом с `AGENTS.md`. Команды Windows-friendly — по одной на строку (в PowerShell `&&` не работает, используй отдельные строки или `;`).

---

## TL;DR

```powershell
# 0. Префлайт (всегда)
git pull
npm install
npm run typecheck
npm test

# 1. Web (EAS Hosting)
npx expo export --platform web
npx eas-cli deploy            # превью-URL — проверить
npx eas-cli deploy --prod     # выкатить на боевой домен

# 2. Мобила (Android APK для себя)
npx eas-cli build --platform android --profile preview
# → EAS даст ссылку/QR на APK, ставишь на телефон

# 3. После деплоя — проштамповать релиз в CHANGELOG.md (см. ниже)
```

---

## 0. Префлайт (перед любым деплоем)

```powershell
git pull                 # взять актуальный main
npm install              # вдруг появились новые зависимости
npm run typecheck        # ноль ошибок
npm test                 # всё зелёное
npx expo install --check # версии нативных пакетов совместимы с SDK
```
Если typecheck или тесты красные — **не деплой**, сначала чини.

**Миграции БД:** если в этом релизе появился новый файл в `supabase/migrations/` — сначала **примени его в Supabase** (SQL в дашборде проекта «Gleb Lab»), потом деплой. Код, ожидающий новую схему, без неё упадёт. Если новых миграций нет — пропусти.

---

## 1. Web — EAS Hosting

```powershell
npx expo export --platform web
```
Соберёт статический билд в `dist/` (web output = `single`, это уже настроено — не меняй на `static`, он падает на auth-роутах).

```powershell
npx eas-cli deploy
```
Задеплоит и даст **превью-URL**. Открой, прокликай ключевое (вход, главная, скан-заглушка, аналитика, экспорт).

```powershell
npx eas-cli deploy --prod
```
Промоутит на **боевой домен**. Готово — web обновлён.

> Web — чистый JS, нативная пересборка не нужна никогда. Любые изменения прилетают этим флоу за пару минут.

---

## 2. Мобила — EAS Build (Android)

```powershell
npx eas-cli build --platform android --profile preview
```
Соберёт **internal APK** (профиль `preview`). Сборка идёт в облаке EAS ~10–20 минут. По окончании EAS даёт ссылку/QR — скачиваешь APK на телефон и ставишь поверх старого.

**Важно (нет OTA):** в проекте не настроен EAS Update, поэтому **каждое** изменение мобильного приложения требует новой сборки — JS-правки «по воздуху» в установленный APK не прилетают. Для разработки используй `npx expo start` + Expo Go / dev-client (живая перезагрузка), а `eas build` — когда нужен установочный билд.

**Когда пересборка обязательна:** всегда, когда менялись нативные части —
- новая нативная зависимость (`expo-print`, `expo-sharing`, `expo-file-system`, `expo-localization`, камера и т.п.),
- изменения в `app.json` (плагины, пермишены, иконки, версия),
- обновление Expo SDK.

JS-only правки на мобилу тоже доезжают только новой сборкой (OTA нет), но они хотя бы не требуют ничего кроме `eas build`.

> Для публикации в Google Play (не «для себя») — профиль `production` + `eas submit`; сейчас флоу internal-distribution (`preview`), этого достаточно.

## 3. После деплоя — закрыть релиз в истории

В `CHANGELOG.md` замени верхний `## [Unreleased]` на датированный релизный блок и заведи сверху новый пустой:

```markdown
## [Unreleased]

## [2026-10-23] — Релиз (web + Android)
<строки, что были в Unreleased>
```

Это можно отдать исполнителю (Codex/Claude Code) одной строкой-промптом или сделать руками. Так всегда видно, что уже у пользователя, а что только в коде.

Проверь на устройстве/в вебе ключевые сценарии (вход, добавление траты, скан, аналитика, экспорт, смена языка) — тесты UI не покрывают.

## Разовая настройка (один раз на машине)

```powershell
npx eas-cli login      # войти в аккаунт Expo (проверка: npx eas-cli whoami)
```
- **Env-переменные** (`EXPO_PUBLIC_SUPABASE_URL`, `EXPO_PUBLIC_SUPABASE_ANON_KEY`) уже заданы в EAS (Plain text, во всех окружениях) — билды и деплой берут их оттуда. Локально они лежат в `.env` (в гите его нет). Если добавишь **новую** `EXPO_PUBLIC_*` переменную — не забудь завести её и в EAS, иначе облачная сборка её не увидит.
- `eas-cli` ставится на лету через `npx eas-cli …` — отдельно устанавливать не обязательно.

## Шпаргалка «что деплоить»

| Что менялось | Web | Мобила |
|---|---|---|
| Только JS/TS (экраны, логика, i18n-строки) | `expo export` + `eas deploy --prod` | `eas build -p android --profile preview` |
| Новый нативный модуль / `app.json` / SDK | то же | **обязательно** `eas build` |
| Новая миграция Supabase | сначала применить в Supabase, потом деплой | то же |
| Ничего (просто посмотреть локально) | `npx expo start --web` | `npx expo start` + Expo Go |

---

## Частые грабли

- **PowerShell `&&`** — не поддерживается. Команды по одной на строку (или `;`).
- **web `output: static`** — крашится на auth-гейтед роутах. Должно быть `single` (уже так).
- **Забыл применить миграцию** — приложение падает на запросах к новой схеме. Миграции применяются вручную в Supabase.
- **Нативный модуль без пересборки** — фича есть в коде, но на телефоне «не работает», пока не сделал новый `eas build`.
- **Долго** — web ~минуты, Android-сборка EAS ~10–20 минут в облаке. Закладывай время.

---

## Хочешь быстрее на мобилу? (опционально, разовая настройка)

Если надоест ждать сборку на каждую JS-правку — можно подключить **EAS Update** (OTA): тогда JS-изменения будут прилетать в установленный билд командой `eas update` за секунды, а полная пересборка нужна только при нативных изменениях. Это отдельная настройка (`expo-updates` + каналы) — скажи, оформлю промптом.
